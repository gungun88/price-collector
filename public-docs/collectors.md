# 采集器贡献

当前自托管版本先关闭旧自动采集链路，避免继续维护第三方后端时代的写库脚本。中转 API 站点、报价和提交线索通过 `/admin` 后台维护。

## 当前维护方式

1. 打开 `/admin`。
2. 审核用户提交的中转 API 线索。
3. 创建或更新站点资料。
4. 在站点下维护报价、模型、倍数、库存和备注。

## 后续采集器要求

如果重新开发自动采集器，应直接写入自托管 PostgreSQL，或通过 Fastify 后端提供的管理 API 写入。不要新增依赖第三方后端平台的写入链路。

采集器至少需要满足：

- 支持 dry-run，只输出将要写入的数据。
- 只更新自己负责的来源，不覆盖人工维护字段。
- 保留原始来源链接、标题、价格、更新时间和错误原因。
- 失败时不删除已有有效报价。
- 支持限速和超时，避免对来源站造成压力。
