# API 中转模型采集流程

当前自托管版本先以后台维护为主，旧自动采集和探测脚本已经停用。中转 API 站点、报价、模型、倍数、库存和备注通过 `/admin` 写入自托管 PostgreSQL。

## 当前数据入口

| 入口 | 说明 |
| --- | --- |
| 用户提交线索 | `/api-transit` 页面提交后进入自托管后端的提交线索表 |
| 后台审核 | 管理员在 `/admin` 审核线索并创建站点 |
| 报价维护 | 管理员在站点下维护模型、分组、倍率、库存、价格说明和备注 |

## 后续自动采集要求

如果重新开发自动采集或实际 Key 探测，应满足：

- 直接写入自托管 PostgreSQL，或调用 Fastify 后端管理 API。
- 支持 dry-run，不直接覆盖人工字段。
- 保留来源 URL、原始模型名、原始倍率、更新时间和错误信息。
- 失败时不清空已有有效报价。
- 探测结果和公开价格分开记录，不把缺 Key 或接口失败当成站点不可用。

## 建议数据流

```text
公开模型目录 / 授权探测 Key
  -> 采集器解析和标准化
  -> Fastify 管理 API
  -> PostgreSQL
  -> 前台中转 API 页面和 /admin 后台
```
